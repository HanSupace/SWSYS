# 2026-11-03 검증 결과

## 실제 DB와 적용 범위

- 연결 대상: 프로젝트 `.env`에 지정된 Supabase PostgreSQL. 접속 비밀값은 기록하지 않음.
- 실행 전: 사용자 10명, 감정기록 100개. 모두 앞서 생성한 전용 시드 데이터였음.
- `seunghak-100.sql` 실제 실행 및 커밋: 사용자 추가 **0명**, 기록 추가 **0개**, 시드 기록 **100개** 일치 확인.
- 기존 사용자와 기록의 전체 JSONB 행, 추천 태그 링크를 스냅샷과 비교하여 기존 데이터 보존 확인.
- 학교 클라우드 PostgreSQL은 접속 정보가 없어 미적용. README의 psql 명령으로 별도 적용 필요.
- 소스 파일 생성과 DB 적용은 별개. Git 커밋·푸시는 이번 작업에 포함되지 않음.

## 실제 스키마 및 제약조건

실제 DB의 information_schema.columns와 pg_constraint를 읽고 아래 구조를 확인했으며, 이 구조에서 SQL 실행도 검증했습니다.

| 컬럼 | 실제 타입 | NULL |
|---|---|---|
| id | bigint, 프로젝트 스키마에서 identity | 불가 |
| user_id | bigint | 불가 |
| latitude / longitude | numeric, 프로젝트 스키마 numeric(10,7) | 불가 |
| emotion_label / emotion_color | varchar(20) | 불가 |
| title | varchar(24) | 불가 |
| location_name | varchar(80) | 불가 |
| description | text | 가능 |
| tags_classified | boolean, 기본 false | 불가 |
| created_at / updated_at | timestamp without time zone, 기본 CURRENT_TIMESTAMP | 불가 |

- `emotion_map_markers.id`: 기본키.
- `emotion_map_markers.user_id → users.id`: 외래키, ON DELETE CASCADE.
- `users.username`, `users.nickname`: 각각 UNIQUE.
- `emotion_map_marker_tags`: (marker_id, tag_code) 복합 기본키.
- 태그 링크의 marker_id → emotion_map_markers.id: 외래키, ON DELETE CASCADE.
- 태그 링크의 tag_code → recommendation_tag_catalog.tag_code: 외래키.
- 시드 계정명: seed_seunghak_v1_01~10. 로그인 불가 비밀번호 값을 사용하고 DB 생성 ID를 참조.

## 최초 삽입·재실행 테스트

실제 PostgreSQL에서 임의 이름의 격리 스키마를 트랜잭션 안에 생성하고 기존 schema.sql을 적용했습니다. 보존 확인용 사용자 1명과 감정기록 1개를 먼저 넣고 시드 본문을 두 번 실행했습니다.

1. 첫 실행: 사용자 +10명, 기록 +100개. 전체 사용자 11명, 기록 101개.
2. 두 번째 실행: 사용자 +0명, 기록 +0개. 전체 사용자 11명, 기록 101개 유지.
3. 두 실행 모두 기존 데이터의 전체 행과 태그 링크 보존 검증 통과.
4. 전체 테스트를 ROLLBACK하여 검증 스키마와 데이터는 남지 않음.

테스트용 SQL은 build/seed/test-seed.sql에 생성했으며 Git 대상이 아닙니다. 실제 앱 테이블은 격리 테스트에서 수정하지 않았습니다.
